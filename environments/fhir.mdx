The most stripped-down clinical environment we run. A seeded FHIR R4 server and nothing else — no user interface, no tool list, no database client. The model gets a shell and an HTTP endpoint.

It is the cleanest available measurement of whether a model can work a clinical record through the standard alone, with nothing interpreting the data on its behalf.

## Execution-graded care plans

The most distinctive thing about this environment is what counts as finishing.

A model asked to build a care plan cannot satisfy the task by writing one. It has to carry the plan into the chart — filing the plan, placing the orders, writing the prescriptions — and it is graded on the resources it actually created.

<Warning>
  An action that exists only as prose has not been taken. A model that describes starting a medication, without a corresponding order in the record, has not started it.
</Warning>

This closes the most common gap between a model that sounds competent and one that is. Recommending the right thing and doing the right thing are scored differently here, on purpose.

## Populations

A run is an environment, a cohort, and a task set. Selecting a patient population before the run means the same task can be evaluated against different clinical populations, and tasks that do not apply to a given cohort are excluded rather than silently failing.

A run became a combination of environment, cohort, and task set, rather than a task pointed at whatever data happened to be loaded.

Registered as its own environment: a screenless FHIR R4 server reached by shell and HTTP, with no interface interpreting the record for the model.
